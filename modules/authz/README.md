# Authz

Authz предоставляет HTTP API выдачи и отзыва доступов и внутренний gRPC API проверки и перечисления прав. Для первоначального назначения Superuser оператор запускает `authz bootstrap-superuser --user-id <UUID>` для заранее зарегистрированного пользователя.

Gateway вызывает gRPC-интерцептор Authz на фазе request headers. Для каждого защищённого маршрута необходимо указать `parameters.module_key` в конфигурации интерцептора. Ключ задаётся администратором Gateway, а не HTTP-клиентом. Отсутствующий или некорректный ключ приводит к отказу. Authz проверяет cookie `session` через Session и разрешает запрос только при наличии доступа или роли Superuser.

Интерфейс интерцептора и внутренний gRPC API предназначены для доверенных компонентов: межсервисная аутентификация и шифрование соединений в текущем проекте не реализованы. Не следует публиковать этот gRPC порт в недоверенную сеть. Для HTTP-маршрутов Authz Gateway сохраняет исходный Host, чтобы проверка Origin работала за прокси.

E2E используют Gateway и защищённый тестовый маршрут к health endpoint Identity. Bootstrap выполняется документированной операторской командой в контейнере Authz. Подключений тестового кода к базам данных нет.
